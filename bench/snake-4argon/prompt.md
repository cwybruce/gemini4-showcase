# 任务 B：贪吃蛇小游戏 — 提示词与测试记录

- 模型：浏览器版 Gemini 4（4 Argon），思考等级：高点（超级详尽）
- 日期：2026-10-14
- 成果：`index.html`（约 12KB，单文件，零外部依赖）

## 最终成功提示词（第 3 次尝试）

```
你是资深前端工程师。直接输出一个完整、可保存为 .html 双击打开的单文件网页代码：不要任何解释、不要 markdown 代码围栏、不要开头结尾的寒暄。硬性要求：①零外部依赖（不引用任何 CDN、在线字体、图片，所有资源内联）；②中文界面；③桌面与移动端都可用；④代码完整可运行。

任务：做一个贪吃蛇小游戏。Canvas 渲染，方向键与触屏滑动控制，计分与最高分（localStorage 持久化），开始/暂停/重开按钮，撞墙或撞到自己时结束并显示结算面板。

注意：代码务必精简紧凑，确保整个 HTML 在一次回复内完整输出，不要超出长度限制。
```

> 说明：最后一句精简要求是第 3 次尝试才追加的（见下方尝试记录），属如实记录的提示词调整。

## 尝试记录

- **第 1 次**：原提示词（无精简句）。生成约 10–15 分钟后在结算 overlay 处被单次回复长度上限截断（缺 canvas / script / 结尾标签）。要求模型从截断处继续，只补出一小段 canvas 片段，随后陷入约 25 分钟推理循环无输出，放弃。
- **第 2 次**：新对话，原提示词。同样在接近位置截断（状态 overlay 内部）。
- **第 3 次**：新对话，原提示词 + 精简句。一次完整输出成功（约 8–10 分钟），纯 HTML、无围栏、无寒暄。

## 测试发现

- 该模型在高思考模式下写长代码时，单次回复长度上限是真实瓶颈；"从截断处继续"的补救成功率低。
- 精简指令能显著降低截断概率，且不明显损伤完成度（成品含：20×20 网格、计分/最高分、开始/暂停/重开、结算面板、新纪录徽章、键盘 WASD/方向键 + 触屏滑动、速度随分数提升）。
- 成品原样入库，未做任何修改（包括 CSS 中一处无选择器的 `{ box-sizing... }` 原样保留，属模型原始输出）。
